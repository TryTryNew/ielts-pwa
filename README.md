## English

### What it is
A flashcard app I built for my own IELTS preparation. It is a **PWA** (Progressive Web App): open it from a URL, add it to your home screen, and keep using it offline. No app store needed.

- Cards grouped by section (Writing Task 1/2, Listening, Reading, Speaking), tagged with Cambridge book / test / part
- **Spaced repetition**: the next review date is scheduled automatically
- Text-to-speech for both sides of a card
- Add cards by hand, or bulk-import JSON generated by an AI
- Statistics page and review calendar
- Sign in with Google to sync cards to the cloud (Firebase)

Live site: https://ielts-pwa-eight.vercel.app

### For developers: run it locally
Regular users only need the link above. To work on the code, serve the project folder with a local server. Opening `index.html` by double-clicking won't work, because browsers block ES modules and Service Workers on `file://` pages. There is no build step.

```bash
python3 -m http.server 8000
```

Then open `http://localhost:8000/index.html`.

> Note: VS Code Live Server ("Go Live") interferes with Service Worker installation. Use the Python server when testing offline mode.

### How data flows
1. **Sign-in**: Google or anonymous. Either way, Firebase issues a `uid`.
2. **Saving**: every add, review, or delete is written **to the device first (localStorage), then to the cloud (Firestore)** under `users/{uid}/cards`.
3. **The UI always reads the local copy.** On startup the app fetches cards from the cloud once, writes them locally, then re-renders. It is not real-time sync.
4. **Security rules**: Firestore only allows reads and writes when the user is signed in and the `uid` in the path matches their own, so users can't see each other's cards.

### Project structure
Originally a single 738-line `app.js` with 34 functions did everything. On 2026-10-23 it was split into the modules below, following two rules: **one file, one job**, and **dependencies point one way** (UI → rules → data).

```
index.html          Markup (5 pages, 3 modals); loads only js/main.js
manifest.json       App name and icons for "Add to Home Screen"
sw.js               Service Worker: network first, cache when offline
js/
├─ main.js          Entry point: startup and wiring
├─ firebase.js      Firebase setup (exports db and auth)
├─ auth.js          Sign-in; the only place that changes the current uid
├─ cloud.js         Cloud read / write / delete
├─ storage.js       Local read / write / backup export
├─ srs.js           Spaced-repetition rule (pure calculation)
├─ dates.js         Date helpers (local time zone)
├─ constants.js     Shared constants such as section names
├─ speech.js        Text-to-speech
└─ ui/
   ├─ nav.js        Page switching (pages register themselves)
   ├─ hub.js        Overview
   ├─ review.js     Review / card flipping
   ├─ analytics.js  Statistics and calendar
   ├─ database.js   Card library
   └─ modals.js     Add-card and AI-import modals
```

### Review interval
After the n-th review, the next review is 2^(n−1) days later, capped at 30 days.
E.g. 1st → 1 day, 2nd → 2 days, 3rd → 4 days, 4th → 8 days … 6th onward → 30 days.

### Tech
HTML, JavaScript (ES modules), Tailwind CSS, Lucide icons, Firebase Authentication, Cloud Firestore, Web Speech API, Service Worker

### Known limitations
- No automated tests; main features are checked by hand after each change
- Changes made offline stay on the device; there is no automatic retry to the cloud when the connection returns
- Anonymous cards are tied to that browser's uid and are lost if browsing data is cleared; Google sign-in is recommended

## 中文

### 這是什麼
一個給自己準備雅思用的單字／錯題記憶卡 App。它是 **PWA**（用網頁做的 App）：用網址就能打開、可以加到手機主畫面、斷網也能用，不需要上架。

- 依科目分類（寫作 Task 1／Task 2、聽力、閱讀、口語），可標註劍橋 C／T／P 題號
- **間隔複習**：每張卡複習完，自動排下一次日期
- 朗讀卡片正反面
- 手動新增，或請 AI 產生 JSON 後一次匯入
- 統計頁與複習日曆
- Google 登入後，卡片同步到雲端（Firebase）

線上版：https://ielts-pwa-eight.vercel.app

### 給開發者：在自己電腦上測試
一般使用者直接打開上面的網址就好。如果要修改程式，請在專案資料夾開一個本機伺服器。不能直接雙擊 `index.html`，因為瀏覽器在 `file://` 模式下會擋掉模組和離線功能。這個專案不需要建置（打包）步驟。

```bash
python3 -m http.server 8000
```

然後打開 `http://localhost:8000/index.html`。

> 注意：VS Code 的 Live Server（Go Live）會干擾 Service Worker 安裝，測離線時請用上面的 Python 指令。

### 資料怎麼流動
1. **登入**：Google 或匿名登入，Firebase 都會給一個 `uid`（每個使用者的編號）
2. **存資料**：每次新增、複習、刪除，**先存本機（localStorage），再送到雲端（Firestore）** 的 `users/{uid}/cards`
3. **畫面永遠讀本機那份**。打開 App 時從雲端讀一次，寫回本機再重畫（不是即時同步）
4. **安全規則**：Firestore 規則只允許「已登入，而且路徑裡的 uid 等於自己」的人讀寫，所以別人看不到你的卡片

### 檔案結構
原本 `app.js` 一個檔案 738 行、34 個函式，什麼都管。2026-10-23 拆成以下模組，原則是**一個檔案只做一件事**、**只往一個方向呼叫**（畫面 → 規則 → 資料）。

```
index.html          畫面（5 個頁面、3 個彈窗）；只載入 js/main.js
manifest.json       App 名稱、圖示，讓它能加到主畫面
sw.js               Service Worker：網路優先，斷網才用快取
js/
├─ main.js          入口：啟動、把各檔案接起來、把按鈕接到函式
├─ firebase.js      Firebase 初始化（交出 db 和 auth）
├─ auth.js          登入；唯一能改目前 uid 的地方
├─ cloud.js         雲端讀、寫、刪（只跟資料庫說話）
├─ storage.js       本機讀、寫、匯出備份
├─ srs.js           間隔複習規則（純計算）
├─ dates.js         日期工具（用本地時區）
├─ constants.js     科目名稱等共用常數
├─ speech.js        朗讀
└─ ui/
   ├─ nav.js        換頁（各頁面用「登記」的方式接上）
   ├─ hub.js        總覽
   ├─ review.js     複習／翻卡
   ├─ analytics.js  統計與日曆
   ├─ database.js   卡片庫
   └─ modals.js     新增卡片、AI 匯入彈窗
```

### 複習間隔規則
第 n 次複習完後，隔 2 的 (n−1) 次方天再複習，最多 30 天。
例：第 1 次 → 1 天、第 2 次 → 2 天、第 3 次 → 4 天、第 4 次 → 8 天……第 6 次起 → 30 天。
